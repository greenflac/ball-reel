## ДОЛГ, КОТОРЫЙ НЕ ЗАКРЫТ, И ЕГО НЕЛЬЗЯ ЗАКРЫТЬ БЕЗ РЕШЕНИЯ ВЛАДЕЛЬЦА

```
# DEBT(2026-08-17): ball_reel/tests/test_reachable.py краснеет на fork_run.
```

**Суть.** `test_reachable` требует, чтобы у каждого модуля в `ball_reel/*.py`
был импортирующий его модуль, либо строка в списке `STANDALONE` с объяснением,
почему модуль работает сам. Список закрытый — и это правильно, добавление туда
должно стоить осознанной строки.

**Почему это неустранимо изнутри форка.** У любого дерева импортов есть корень.
Сейчас корень — `fork_run`, он зовёт остальные семь модулей форка. Какой модуль
ни поставь корнем, у него по определению не будет импортирующего. Значит корень
обязан быть в `STANDALONE` — то есть в **существующем файле**, а брифинг прямо
запрещает править существующие файлы.

Обойти это можно было бы циклическим импортом (`fork_seam` тянет `fork_run`
внутри функции) — тогда корня формально не станет. **Это не сделано
намеренно:** докстринг самого сторожа говорит, что список не должен быть
«способом заглушить тест», а циклический импорт ради зелени — тот же способ,
только грязнее.

**Цена сейчас.** `python3 -m ball_reel.codeaudit --quick` останавливается на
красных тестах, то есть гейт не проходит целиком. Все остальные тесты зелёные,
включая все восемь модулей форка.

**Как закрывается — одна строка, решение владельца:**

```python
# ball_reel/tests/test_reachable.py, в STANDALONE
"fork_run": "точка входа форка, запускается человеком",
```

Ровно та же формулировка, что уже стоит там у `run_local`, `produce`, `gen`,
`preflight_gpu` — семи точек входа существующего пайплайна. То есть это не
исключение из правила, а применение правила к восьмой точке входа.

## Дефекты, найденные и закрытые в этой смене

**1. `git add -A` подмёл чужой временный файл.** `test_codeaudit` создаёт
`codeaudit_clone_probe.tmp` **неотслеживаемым** и проверяет, что клон из индекса
его не подхватывает. Закоммитив его, я сделал файл отслеживаемым и уронил ровно
этот сторож. Закрыто `git rm --cached`; дальше в этой ветке только явные пути.

**2. Произведённый граф Comfy не был подключён.** Первая редакция `fork_comfy`
вырезала кастомные ноды и клала три загрузчика РЯДОМ, не соединяя их. Аудит
говорил «ЧИСТО» — кастомных нод нет, оборванных связей нет, — а четыре входа
`WanAnimateToVideo` остались без питания: вырезание сняло связи 704, 705, 706,
707. Закрыто подключением и отдельной проверкой `unfed_inputs`, которая умеет
краснеть.

**3. Локальный канал оси протечки судился без порога.** Замер планки показал,
что локальный шум кодека в шестнадцать раз выше среднего (0.071895 против
0.004513 при crf 18). Судить максимум средней планкой значило бы объявлять
протечкой каждый блок сжатия; не судить — терять канал, ради которого он
заведён. Закрыто второй планкой.

**4. Мутационный тест краснел не по делу.** Проверка ширины кольца шовной оси
стояла на фикстуре с идеально гладкой серединой, где отношение равно нулю при
любой ширине. Подмена константы ничего не показывала. Закрыто фикстурой, где
фактура меняется с глубиной.

**5. Первая редакция `axis` считала дорогое до дешёвого.** Негодный референс
отвергался уже после полного прохода по набору. Закрыто проверкой обоих якорей
до первого обращения к прибору (П2).

## Второй долг: `docs/NUMBERS.md` разошёлся с веткой

```
# DEBT(2026-08-17): docs/NUMBERS.md называет размер набора до форка.
```

Ветка добавила 236 тестов (восемь модулей форка со своими наборами), и число в
`docs/NUMBERS.md` теперь описывает состояние ДО спринта. По правилу проекта
документ, разошедшийся с кодом, — дефект, а не косметика.

**Почему не исправлено здесь:** `docs/NUMBERS.md` — существующий файл, а
брифинг запрещает править существующие. Ни один тест на этом не краснеет:
`test_docs_numbers` запрещает называть размер набора ВНЕ этого файла и сверяет
число мутаций, но актуальность самого числа проверить статически нельзя — его
можно только прогнать. Поэтому расхождение тихое, и записано оно здесь.

Свежее число — прогоном, той же командой, что стоит в самом `NUMBERS.md`:

```
python3 -m unittest discover -s ball_reel/tests -t . -p 'test_*.py'
```

Вывод на 2026-08-17 в этой ветке: **1 отказ** (`test_reachable`, долг выше),
13 пропусков. Число тестов намеренно не повторяю здесь — его место в
`docs/NUMBERS.md`, и вписать его туда должен тот, кому можно править файл.
