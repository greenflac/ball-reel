## Оценка решения

**Годно частично.** Разделяю два разных «403», их смешение — главный дефект постановки:

- **403/WAF на целевом сайте** (Cloudflare, антибот). Здесь скилл-ресёрчер действительно
  помогает: он подменяет «сходи curl'ом на сайт» на «спроси поисковый/extraction API».
  Это рабочий класс решения.
- **403 от egress-прокси окружения** (то, что наблюдается тут по clawhub.ai, duckduckgo.com,
  r.jina.ai). Скилл это **не чинит принципиально**: запрет стоит до сети, а не на сайте.
  Лечится только списком разрешённых доменов в окружении (Ц3), и это решение владельца.

Риски конкретно этого способа установки:

- Слаг `web-searcher` не подтверждён (Ц10). Ставить неподтверждённое имя в `~/.claude/skills`
  — значит отдать всем будущим сессиям инструкции неизвестного происхождения.
- Скилл = промпт + скрипты, которые исполняет агент. Установка в `~/.claude/skills` —
  это глобальное доверие во всех проектах, без пина версии и без ревью диффа при `update`.
- Каталог `~/.claude/skills/synced/` уже управляется синхронизацией; ставить туда же
  рядом чужое — источник конфликтов при перезаписи.
- Скилл почти наверняка потребует ключ внешнего API (Brave/Exa/Parallel/SearXNG).
  Без ключа он даст ноль результатов, что по Р1 обязано читаться как «не смогли проверить»,
  а не как «ничего не найдено».

## План внедрения

Ш0. **Разблокировать реестр или отказаться от него.** Попросить у владельца окружения
    добавить `clawhub.ai` в allowlist. Не открыли — ставим скилл из локального файла/репозитория,
    команда из задачи в облаке не применима. Стоп-условие (Ц9): если к концу следующей сессии
    домен не открыт и локального источника скилла нет — фиксируем «внедрение остановлено,
    причина: источник недоступен» и делаем Ш3 (свой тонкий скилл) без чужого кода.

Ш1. **Ревью до установки, не после (Ц5, Ц10).** Поставить во временный каталог, не в `~/.claude`:
    `npx clawhub@0.23.3 --dir /tmp/skill-review install web-searcher` (версия CLI пинуется),
    затем прочитать SKILL.md и все скрипты глазами (П3): какие хосты дёргает, какие ключи
    читает из env, что исполняет. Лицензия скилла — отдельно от лицензии CLI;
    `non-commercial`/`research-only` помечать. Установка с `--force` поверх флага
    `isSuspicious` — запрещена.

Ш2. **Ключ и негативный контроль (И5) до подключения.** Завести ключ выбранного поискового API,
    прогнать два входа: (а) запрос, который обязан вернуть результаты; (б) запрос с заведомо
    битым ключом — обязан вернуть «не смогли», а не пустой список. Оба вывода — в отчёт.

Ш3. **Обёртка вместо голого скилла.** Подключать не скилл напрямую, а субагента
    `.claude/agents/researcher.md`, который: имеет только Read/Grep/WebSearch/WebFetch/Bash-curl,
    возвращает три исхода (`найдено` / `не найдено` / `не смогли: <причина, хост, код>`) (Р1),
    печатает рядом `проверено N источников, не смогли K` (Р2), и в каждом ответе даёт URL
    источников. Порядок инструментов — от дешёвого к дорогому (П2): WebSearch → WebFetch →
    внешний API → curl.

Ш4. **Глобальность — осознанно.** Чтобы «в любой сессии»: класть в `~/.claude/skills/<имя>/`
    (не внутрь `synced/`), версию скилла зафиксировать в файле `VERSION` и не запускать
    `clawhub update` без чтения диффа. Телеметрию выключить: `CLAWHUB_DISABLE_TELEMETRY=1`
    в окружении, если не хотим слать slug/owner/version в реестр.

Ш5. **Гейт вместо договорённости (Ц7).** Тест, который дёргает субагента на фиксированном
    запросе с замоканным HTTP (сеть в тестах запрещена, Т4) и проверяет, что при коде 403
    возвращается именно исход «не смогли», а не «не найдено». Мутация константы (Т1):
    поменять маппинг 403 → «не найдено» — тест обязан покраснеть.
