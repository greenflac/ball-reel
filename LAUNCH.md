# Запуск на тестовой машине: блюпринт

Один маршрут от чистой машины до клипа с отчётом. Шаги идут по возрастанию
цены: каждый следующий дороже предыдущего, поэтому отказ случается как можно
раньше и стоит как можно меньше.

Глубокий разбор отказов — `DEMO_RUNBOOK.md`. Здесь только маршрут.

---

## Что получится на выходе

Три файла, и только первый из них — «результат»:

| файл | что это |
|---|---|
| `run_out/clip.mp4` | вертикальный клип: человек **с фото** выполняет движение **с видео** |
| `run_out/report.json` | вердикт по каждой оси с числом, а не «ок» |
| `run_out/lora/` | обученный адаптер личности (если запускали с `--train-lora`) |

Отчёт трёхзначен по каждой оси: **прошло**, **не прошло**, **не смогли
измерить**. Третье — не поблажка, а отдельный вердикт: лицо в кадре 78 px при
баре 100 значит «нечем судить», и выдавать это за «личность в порядке» нельзя.

---

## Откуда что берётся: два референса и одна метрика на каждый

Правило продукта: **всё про человека — из фото, всё про движение — из видео,
ничего не выдумывается.** Отсюда разведены и каналы, и меры.

| что переносим | откуда | чем впрыскивается | чем ПРОВЕРЯЕТСЯ |
|---|---|---|---|
| личность | `face.jpg` | IP-Adapter FaceID + обученная LoRA | ArcFace `buffalo_l`, бар 0.35 |
| телосложение | `face.jpg` | ретаргет костей в условиях | доля измеренных костей в манифесте |
| движение | `driving/*.jpg` | ControlNet OpenPose (условия от DWPose) | MediaPipe Pose, бар 0.25 |
| траектория | `driving/*.jpg` | — | `action`: направление 0.50, амплитуда 0.35 |
| одежда, окружение | **промт** | текст | CLIP LAION B/32, контрастная маржа 0.012 |

**Судья независим от судимого, и это не лозунг.** Условия снимает DWPose —
проверяет MediaPipe. Набор для LoRA порождает шлюз — отбирает FaceNet — судит
ArcFace. Спросить генератор, получилось ли у него, нельзя ни в одном месте
пайплайна; проверка разведения написана кодом (`dataset.independence_report`) и
стоит первой и в предполёте, и в приёмке.

## Стек, поэлементно

```
вход:  face.jpg                    driving/*.jpg
         |                              |
         |                        DWPose (YOLOX+RTMPose) -> скелет
         |                              |
         |                        ретаргет под телосложение с фото
         |                              v
         |                        conditions/*.png + manifest.json
         |                              |
   [ порождение набора ]                |
   nanobanana (шлюз)                    |
   -> отбор FaceNet, бар 0.30           |
   -> подписи ЗАМЕРОМ кадра             |
         v                              |
   [ обучение LoRA ]                    |
   SD1.5 UNet + peft, ранг 8            |
   -> pytorch_lora_weights.safetensors  |
         |                              |
         v                              v
   +----------------------------------------+
   |  SD1.5 + AnimateDiff motion adapter    |
   |  + ControlNet OpenPose (поза)          |
   |  + IP-Adapter FaceID   (лицо)          |
   |  + LoRA личности       (обученная)     |
   |  + Motion LoRA         (камера, опц.)  |
   +----------------------------------------+
         |
         v
   доводка лица (--refine, опц.)
         |
         v
   ГЕЙТ: 13 осей, все меряют            <- MediaPipe, ArcFace, CLIP
         |
         v
   ПЕЧАТЬ: sha256 судимых кадров (GateSeal)
         |
         v
   апскейл Swin2SR x2 (--upscale, опц.)
         |
         v
   clip.mp4 + report.json
```

Порядок «гейт → печать → апскейл» не переставляется: печать фиксирует
**те кадры, которые судили**, и делает подмену после суда невозможной.

**Внутри контура генерации нет ни одного сетевого вызова.** Шлюз участвует
только на шаге порождения набора, до обучения, и его можно пропустить целиком.

## Маршрут

### Шаг −1 — установка. Torch ставится ПЕРВЫМ и ОТДЕЛЬНО

Порядок здесь не стилистический: **`pip install torch` без индекса даёт на
Windows сборку БЕЗ CUDA**, и она молча перекрывает правильную. Получается
`2.x.x+cpu`, `cuda.is_available() == False` — и выясняется это на первом кадре,
уже после того как скачаны гигабайты весов. Ровно поэтому torch не живёт в
`requirements-gpu.txt`: requirements-файл не умеет сказать «эту строку тащить из
другого индекса».

```bash
# 1. Какая CUDA у драйвера — смотреть в шапке вывода:
nvidia-smi
```

```bash
# 2. Torch под эту CUDA. КОМАНДУ ВЗЯТЬ В СЕЛЕКТОРЕ, а не отсюда:
#    https://pytorch.org/get-started/locally/
#    Вид у неё такой (cuXXX подставляет селектор):
pip install torch torchvision --index-url https://download.pytorch.org/whl/cuXXX
```

Точный тег `cuXXX` в этом файле НЕ ЗАПИСАН намеренно: `download.pytorch.org`
закрыт прокси среды разработки (403), список колёс оттуда прочитать нельзя, а
писать номер по памяти — это выдавать догадку за проверку. Правило без номера:
**CUDA драйвера (шапка `nvidia-smi`) не ниже CUDA сборки torch.** Ниже — падает
не «нет CUDA», а `no kernel image is available for execution on the device` на
первом же ядре.

```bash
# 3. Остальное — из файла, где версии закреплены осознанно:
pip install -r requirements-gpu.txt

# 4. Отбирающий распознаватель для набора LoRA — ОТДЕЛЬНО и с --no-deps,
#    иначе pip вправе снести CUDA-колесо torch ради своего:
pip install --no-deps facenet-pytorch

# 5. ffmpeg (без него кадры соберутся, а ролика не будет):
#    Linux: apt install ffmpeg    Windows: winget install ffmpeg
```

**Проверка установки — одной командой, до всего остального:**

```bash
python3 -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.version.cuda)"
```

Годный ответ выглядит так: `2.x.x+cu126 True 12.6`. Если видите `+cpu` или
`False` — вернитесь к шагу 2, ничего дальше запускать не нужно: весь маршрут
упрётся в это. `pip install torch` поверх сломанной установки не чинит её,
нужно `pip uninstall torch torchvision` и заново из индекса.

Веса (~7 ГБ) поедут сами при первом запуске в `HF_HOME`. Диска нужно **от 30 ГБ**
свободных; предполёт шага 1 проверяет это до генерации, а не после.

### Шаг 0 — что за машина (10 секунд, ничего не ставит)

```bash
cd ball_reel
python3 -c "from ball_reel.device import describe, smi_probe; print(describe()); print(smi_probe())"
```

Печатает устройство (`cuda` / `xpu` / `mps` / `cpu`), провайдеры onnxruntime и
сверку **версии драйвера с версией сборки torch**. Последнее важнее, чем
кажется: драйвер ниже сборки падает не «нет CUDA», а `no kernel image is
available` на первом же ядре — то есть после загрузки семи гигабайт весов.

Дальше всё считается под то число видеопамяти, которое здесь напечаталось. В
командах ниже `--vram 6` — замените на своё.

### Шаг 1 — предполёт (минуты, ничего не генерирует)

```bash
python3 -m ball_reel.preflight_gpu --conditions kit/conditions --face kit/face.jpg --vram 6
```

Проверяет по возрастанию цены: пакеты (1 мс на `find_spec`) → диск → torch →
драйвер → VRAM → веса → ffmpeg → модели позы и лица → условия → driving-кадры →
лицо. У каждой строки есть **лечение**, а не только вердикт.

Строка `НЕПРОВЕРЕНО` — это не «в порядке». По каждой такой решать отдельно.

### Шаг 2 — набор для LoRA (~3 минуты, ~1.75 pollen)

```bash
python3 -m ball_reel.dataset --face kit/face.jpg --out ds \
        --trigger ohwx_person --generate 20 --yes
```

Без `--yes` печатается только смета и не тратится ничего.

Что должно получиться (замер 2026-08-14 на этом ките):

```
взято 14 из 20 (70%) при баре 0.30
набор: 23 кадров, шагов-эквивалентов 27
  real 1   augmented 8   generated 14
независимость: судья независим от порождения и отбора
```

**Смотреть глазами обязательно.** Откройте 3-4 кадра из `ds/img/gen_*.png`.
Ищете одно: **разную одежду и разные места**. Если во всех кадрах одна и та же
одежда — набор испорчен, и никакое обучение это не чинит: одежда в подпись не
идёт (подпись меряет кадрировку, поворот и свет), значит одинаковая прилипнет к
триггеру, и LoRA выучит не человека, а человека в этом наряде. Именно на этом
был пойман `kontext` и заменён на `nanobanana`.

Отсев ниже 40% — шаг сам скажет об этом и **не посоветует поднять бар**:
поднять бар значит починить измеритель вместо измеряемого. Отброшенные кадры
лежат в `ds/generated/dropped` с дистанциями в `synth_report.json`.

### Шаг 3 — обучение LoRA (сначала вхолостую, потом всерьёз)

```bash
python3 -m ball_reel.train --dataset ds --out lora_out --vram 6 --dry-run
python3 -m ball_reel.train --dataset ds --out lora_out --vram 6
```

`--dry-run` не грузит весов. Ожидаемый вывод предполёта — шесть `PASS` и план:

```
план: 270 шагов, ранг 8, разрешение 512, AdamW8bit
      270 шагов = 27 кадров с повторами x 10 проходов, потолок плана 1200 не достигнут
```

Первая строка живого запуска — **счётчик обучаемых параметров ДО первого шага**.
Ожидаемое значение снято на настоящих весах SD1.5 (не оценка):

```
обучаемых 1594368 из 861115332 (0.185%) — адаптер на месте
```

Ноль или «почти ноль» здесь — отказ, а не примечание. Обучение, в котором
ничего не обучается, идёт неотличимо от настоящего: лосс падает от шума, время
тратится, файл появляется.

По памяти план сходится с запасом (`python3 -m ball_reel.lora --vram 6`):
нужно **~4.41 ГБ из 6.0**, из них 1.0 ГБ — оценка активаций, а не замер.

**Лосс сам по себе ничего не доказывает** — он падает и у адаптера, выучившего
фон. Приёмка делается на пробных промтах (`lora.probe_prompts`, `lora.accept`) и
**одной командой пока не собрана** — это ручной шаг: сгенерировать по пробным
промтам с адаптером и без, сравнить. Не выдавать падение лосса за приёмку.

*Не исполнялось на карте ни разу.* Проверена механика (адаптер садится на
проекции внимания, шаг двигает все его тензоры, сохранённое читается загрузкой
и меняет выход), сам проход на настоящих весах — нет. Закладывайте время.

### Шаг 4 — прогон вхолостую (ничего не генерирует)

```bash
python3 -m ball_reel.run_local --engine animatediff \
        --face kit/face.jpg --conditions kit/conditions \
        --prompt "..." --vram 6 --smoke
```

`--smoke` собирает пайплайн, печатает **что реально прицепилось** (`active_loras`
— опрошено у самой модели, а не у своих аргументов) и останавливается **до**
генерации: у AnimateDiff нет дешёвого одиночного кадра, кадры считаются
совместно одним проходом. Дешёвый способ поймать «LoRA не доехала» до того, как
за неё заплачено временем.

**Строка `faceid` будет красной, и это ожидаемый исход, а не поломка.** Ключи
FaceID-LoRA адресованы attention базового SD1.5, а после модуля движения UNet
стал `UNetMotionModel` с другой размерностью (640 против 320). Проекция
эмбеддинга при этом жива: 16 процессоров внимания из 72 подменены. Личность
обусловлена, но наполовину — ровно поэтому нужна своя LoRA.

Строка `subject` — это наш адаптер, и **она должна быть зелёной**.

### Шаг 5 — полный прогон

```bash
python3 -m ball_reel.run_local --engine animatediff \
        --face kit/face.jpg --conditions kit/conditions \
        --prompt "a person in a bright red tank top and black shorts, in a sunlit gym" \
        --lora lora_out --lora-scale 0.8 \
        --vram 6 --out run_out
```

Обучение можно сделать ступенью того же прогона — тогда адаптер и клип связаны
одним запуском, и в отчёте их не перепутать:

```bash
python3 -m ball_reel.run_local ... --train-lora ds --train-epochs 10
```

`--lora` и `--train-lora` вместе запрещены: какой из двух оказался в кадре,
отчёт потом не различит.

**Промт нарочно не совпадает ни с одним референсом.** Ни фото (розовое платье),
ни driving-видео (тёмная спортивная форма) не содержат красной майки — значит
ось `semantic` меряет настоящее следование заказу, а не совпадение с тем, что и
так было в кадре.

### Шаг 6 — доводка и апскейл, по одному за раз

```bash
python3 -m ball_reel.run_local ... --refine
python3 -m ball_reel.run_local ... --refine --upscale
```

Обе ступени выключены по умолчанию и включаются **по одной**: три неизвестных
разом дают один отказ и трёх подозреваемых.

Про доводку надо знать одно: лицо она не восстанавливает, а **порождает**, и
ArcFace после неё смещён в оптимистичную сторону. Модуль говорит это сам.

## Лестница отступления, если не влезло в память

Готова заранее, чтобы не изобретать её на машине. Спускаться **по одной
ступени**, снизу вверх по цене качества:

1. `--stride 2` — вдвое меньше кадров, длительность та же;
2. разрешение 448, затем 384 — лицо мельче, гейт слепнет раньше;
3. `gradient_checkpointing` уже включён в плане обучения (−1.5 ГБ, +30% времени);
4. `--from-frame N` — считать не всю последовательность.

Первым делом смотреть, что печатает `animate.plan`: он считает память до
загрузки весов и говорит, чего именно не хватает.

## Что заведомо не сработает — сказать вслух самим

| что | почему | статус |
|---|---|---|
| строка `faceid` в списке LoRA | размерность после модуля движения | **ожидаемо красная** |
| личность на полном росте | лицо 78 px при баре 100 | вердикт «НЕ ПРОВЕРЕНО», не «плохо» |
| голени по телосложению с фото | на портретной рефке коленей не видно | донорские, помечено в манифесте |
| `--garment-ref` | единственный адаптер занят лицом | прогон отказывает внятно |
| IP-Adapter FaceID в коммерции | research-only, дословно из карточки | **улажено** 2026-08-14; замена всё равно намечена в `PRIOR_ART.md` §10.1 |
| веса FaceNet (отбор набора) | vggface2 research-only, только отбор набора | **улажено** 2026-08-14 |

Порог идентичности **требует перекалибровки**: измерено, что тот же человек в
трудной позе даёт до 0.570 при баре 0.35. Часть прошлых отказов «не тот
человек» была ложной. Это известно и записано, а не обнаружится при зрителе.
