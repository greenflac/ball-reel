# ОТБИРАЮЩИЙ РАСПОЗНАВАТЕЛЬ для набора LoRA (`ball_reel.synth`). Ставить
# ОТДЕЛЬНО и С --no-deps:
#
#     pip install --no-deps facenet-pytorch
#
# Причина та же, что у torch, и цена та же. У `facenet-pytorch` в зависимостях
# стоит свой torch, и pip, разрешая их, вправе снести уже поставленное колесо
# с CUDA ради колеса с PyPI — то есть повторить ровно ту поломку, из-за которой
# torch не живёт в этом файле. С `--no-deps` не тянется ничего: всё, что ему
# нужно (torch, torchvision, numpy, pillow, requests), уже стоит.
#
# Зачем он вообще: отбирать порождённые кадры ArcFace'ом нельзя — судья вошёл
# бы в отбор, и независимость LoRA от ArcFace потерялась бы там, где её
# собирались получить. Это ДРУГОЕ семейство и другие веса.
#
# torchvision нужен ему самому; ставится вместе с torch из того же индекса.
#
# PIP БУДЕТ РУГАТЬСЯ НА facenet-pytorch, И ЭТО НАДО ПЕРЕТЕРПЕТЬ. Дословно:
#
#   facenet-pytorch 2.6.0 requires numpy<2.0.0, but you have numpy 2.5.2
#   facenet-pytorch 2.6.0 requires torch<2.3.0, but you have torch 2.13.0+cu130
#   ... то же про Pillow и torchvision
#
# Это УСТАРЕВШИЕ ПИНЫ в метаданных пакета, а не несовместимость. Проверено
# исполнением на связке torch 2.13.0+cu130 / numpy 2.4.6 / pillow 12.3.0:
# MTCNN находит лицо, InceptionResnetV1 считает эмбеддинг, и вся калибровка
# порога отбора (71 кадр, 2485 пар своих) снята именно на ней.
#
# ЧЕГО НЕЛЬЗЯ ДЕЛАТЬ: чинить это по совету pip. `pip install "numpy<2"
# "torch<2.3"` снесёт CUDA-сборку torch и вернёт установку к началу — то есть
# ровно к той поломке, ради предотвращения которой torch и вынесен из этого
# файла. Предупреждение игнорируется, версии не откатываются.
