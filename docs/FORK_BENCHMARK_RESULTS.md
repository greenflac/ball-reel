## 2. Kling: схема ВЫТАЩЕНА ЦЕЛИКОМ из ответов сервиса

Первая смена писала: «HTTP-схема Kling неизвестна целиком: ни база, ни путь,
ни способ авторизации не подтверждены ничем». **Все три пункта закрыты.**

### 2.1. Авторизация: подозрение первой смены ОПРОВЕРГНУТО

Первая смена числила первым подозреваемым форму ключа: `KLING_KEY` — 57
символов, двоеточий 0, «на пару AccessKey/SecretKey не похож».

ЗАМЕРЕНО: `Authorization: Bearer <KLING_KEY>` принимается сервисом.

    GET /v1/videos/text2video, Bearer <KLING_KEY>   200 {"code":0,"message":"SUCCEED"}
    то же без заголовка вовсе                       401 {"code":1001,"Authorization is empty"}
    то же с мусорным ASCII-ключом                   {"code":1002,"token was expected
                                                     to have 3 parts, but got 0"}

Прибор различает «ключа нет», «ключ не тот» и «ключ принят» — три исхода, а не
два. **Никакой JWT собирать не надо.**

Оговорка, чтобы наблюдение не выдавалось за большее: сообщение про «3 parts»
показывает, что у Kling есть и JWT-ветка. Наш ключ (точек 0) в неё не попадает
и принимается напрямую. ПОЧЕМУ сервис принимает оба вида — НЕПРОВЕРЕНО;
ЧТО принимает наш — доказано ответом.

### 2.2. Путь эндпоинта: подтверждён, с негативным контролем

GET списка задач оказался бесплатным детектором существования метода.

| путь | ответ | |
|---|---|---|
| `/v1/videos/motion-control` | **200 code 0 SUCCEED** | ЕСТЬ |
| `/v1/videos/motion_control` | 404 | нет |
| `/v1/videos/motioncontrol` | 404 | нет |
| `/v2/videos/motion-control` | 404 | нет |
| `/v1/videos/ZZZ_negative_control_ZZZ` | 404 | нет, контроль (И5) |
| `/v1/videos/text2video`, `image2video`, `multi-image2video`, `video-extend`, `lip-sync`, `effects` | 200 | есть |

Обе базы (`api.klingai.com` и `api-singapore.klingai.com`) отвечают одинаково.

### 2.3. Поля: каждое имя и допустимые значения названы САМИМ СЕРВИСОМ

Схема вытащена лестницей отказов — пустое тело, сервис называет недостающее
поле, добавляем, называет следующее. Ни одно имя не взято из памяти (Ц10).

| поле | как подтверждено | значения |
|---|---|---|
| `model_name` | «model_name must be 'kling-v2-6' or 'kling-v3'» | **сервис назвал сам**; `kling-v1` отвергнут |
| `image_url` | «imageUrl: must not be blank» | URL **или base64** |
| `video_url` | «videoUrl: must not be blank» | **только URL** |
| `mode` | «video mode must be specified» | `std` принят; прочие не проверялись |
| `character_orientation` | «character orientation must be specified» | приняты `0` и `1`; `2`, `3` и все слова отвергнуты |

Имена-кандидаты `orientation`, `char_orientation`, `character_direction`
отвергнуты сервисом — то есть проба различает верное имя и похожее.

### 2.4. Асимметрия загрузки: фото байтами можно, видео — нельзя

Замерено отдельно, и это меняет план:

| что послали | ответ |
|---|---|
| `image_url` = base64 реального фото | прошло до проверки баланса |
| `image_url` = мусор | «File is not in a valid base64 format» |
| `video_url` = base64 реального mp4 (672 КБ) | «Video URL is invalid» |
| `video_url` = мусор | «Video URL is invalid» |

Негативный контроль различает случаи для фото и НЕ различает для видео —
значит base64 в `video_url` не поддерживается, а не «не долетел».

**Следствие: для Kling нужен внешний HTTP-хост под драйвинг.** CDN fal.ai на
эту роль не годится, пока его аккаунт заперт балансом. Это открытый вопрос,
которого до этой смены в списке не было.

## 3. fal.ai: подтвердить схему НЕ УДАЛОСЬ, и негативный контроль спас от вранья

Это место стоит прочесть целиком: здесь чуть не появилось ложное
подтверждение, и отменил его именно негативный контроль (И5).

**Соблазнительное наблюдение.** Пустой POST на `fal-ai/wan/v2.2-14b/animate/replace`
даёт 403 lock, а на `fal-ai/nosuchvendor/nosuchmodel/nosuchmode` — 404
«Application "nosuchvendor" not found». Читается как «имя эндпоинта
существует, проверка баланса идёт после резолва».

**Негативный контроль это опроверг:**

    fal-ai/wan/v2.2-14b/animate/replace      403 lock
    fal-ai/wan/v2.2-14b/animate/replaceXX    403 lock   <- ВЫДУМАННЫЙ, тоже 403
    fal-ai/wan/v9.9-99b/animate/replace      403 lock   <- ВЫДУМАННЫЙ, тоже 403
    fal-ai/flux/dev                          403 lock
    fal-ai/nosuchvendor/...                  404

Без ключа сервис говорит прямо: `«Cannot access application "fal-ai/wan"»`.

**Резолвится ТОЛЬКО первый сегмент.** Подтверждено существование приложения
`fal-ai/wan` — и НИЧЕГО про хвост `v2.2-14b/animate/replace`, ничего про поля.
Без негативного контроля в отчёт уехало бы «имя эндпоинта подтверждено», и это
было бы неправдой.

**Обходных путей к схеме не нашлось:** без ключа 401, с ключом 403 lock,
`queue.fal.run/<ep>/openapi.json` — 405, три пути на `rest.fal.ai` — 404, а
публичный OpenAPI живёт на `fal.ai`, закрытом политикой. Обходить её нельзя (Ц3).

**Значит пункт задания «снять фактическую схему fal.ai» закрывается первым же
вызовом после пополнения баланса, и не раньше.**

### ГЛАЗАМИ (П3): расхождений между референсом и драйвингом ШЕСТЬ, а не одно

Кусок просмотрен по шести точкам (кадры 0, 20, 40, 60, 80, 100).
**Один и тот же человек, монтажных резов 0** — требование мануала §2
выполнено и проверено, а не принято на слово. Темноволосая женщина в очках,
тёмно-синий спортивный топ и легинсы, сидит на сером фитболе, ровный
комнатный свет, камера неподвижна, движение малоамплитудное. **Лицом в камеру
на всём протяжении куска.**

Референс `assets/photoref_profile.jpg` посмотрен рядом: блондинка с очень
длинными светлыми волнистыми волосами, розовое корсетное платье-пачка с
бантом, снята СО СПИНЫ, голова повёрнута через плечо, сад с розами, закатный
контровой свет, стоит.

**Первая смена назвала одно расхождение — ракурс. Их шесть:**

| | референс | драйвинг |
|---|---|---|
| ракурс | со спины, голова через плечо | лицом в камеру |
| волосы | очень длинные, светлые, распущенные | тёмные, собранные |
| одежда | пышная юбка-пачка | облегающие легинсы и топ |
| очки | нет | есть |
| свет и фон | закатный контровой, сад | ровный комнатный, стена |
| поза | стоя | сидя на фитболе |

**Это усиливает довод за страховочный второй ролик, а не ослабляет его.**
Если бы объяснение было одно (ракурс), второй ролик разделял бы две гипотезы.
Объяснений шесть — и второй ролик, где референсом взят кадр самого драйвинга,
снимает **все шесть разом**. Без него плохой эталон не будет означать ничего:
списать его можно будет на любое из шести расхождений, и стоп-условие §10
сработает нечестно.

Отдельно: ArcFace согласуется с глазами. 1.0217 между актёром драйвинга и
фото клиента — это заведомо разные люди, что видно и без прибора (брюнетка в
очках против блондинки). Прибор проверен на боевом куске с той стороны, где
он обязан сказать «далеко».

### Починен дефект прибора: код возврата не зависел от вердикта

`fork_bench_measure` возвращал **0 всегда** — и на «не годно» тоже. В CI такой
прибор вечно зелёный (Р2). Греп по форме дефекта дал 1 место в `fork_bench`
(в `ball_reel/tests/*` код возврата даёт раннер pytest, там формы нет;
`ball_reel/*` не правился по Ц2). Теперь три исхода различимы кодом:
`годно` 0, `не годно` 1, `не смогли проверить` **2** — намеренно не 1, чтобы
«не смогли измерить» не снималось тем же способом, что «измерили и плохо».
Проверено прогоном на всех трёх исходах.

Заодно назван вслух молчаливый выбор: агрегатный вердикт берётся от режима
без отсева, и теперь прибор это печатает, а не решает за читателя.

## 8б. Побочно замерено: ffmpeg ставится, и рез за концом больше не врёт

В контейнере снова не было ни `ffmpeg`, ни `ffprobe`. `pypi.org` открыт, и
`pip install imageio-ffmpeg` кладёт `ffmpeg` 7.0.2 — то есть резать будет чем,
как только появится драйвинг. `ffprobe` пакет по-прежнему не кладёт, поэтому
заменитель на PyAV (`fork_bench_prober.py`) остаётся нужен.

Заодно проверен старый дефект команды мануала — «при резе за концом ролика
ffmpeg молча отдаёт файл целиком». **На команде с `-frames:v` он НЕ
воспроизводится:** рез из 1.33-секундного `demo/clip.mp4` (короче заказанных
4.21 с) дал файл 261 Б, в котором PyAV не находит ни одного видеопотока, а
прибор ответил `не смогли проверить`, а не `годно`. Против входных 672 097 Б
это ни при каком чтении не «копия». Ещё один довод за `-frames:v` против
команды из мануала.

## 9. Чем пользоваться

`fork_bench/` — пять приборов, все прогнаны, все с тремя исходами:

| файл | что делает | проверен |
|---|---|---|
| `fork_bench_preflight.py` | что блокирует прямо сейчас: домены, ключи, **баланс**, вход | да, мутациями констант в обе стороны |
| `fork_bench_input.py` | точный рез 101 кадра + проверка ПОСЛЕ реза | да: годно / нет исходника / рез за концом |
| `fork_bench_fal.py` | прогон fal.ai; отличает «денег нет» от «схема не та» | до lock'а (третий исход) |
| `fork_bench_kling.py` | прогон Kling по ПОДТВЕРЖДЁННОЙ схеме | до баланса (третий исход) |
| `fork_bench_measure.py` | `fork_video.frames` + `fork_identity.distances`, оба режима отсева | да, на боевом фото |
| `fork_bench_prober.py` | заменитель `ffprobe` на PyAV | да, на трёх входах |

Существующие модули `ball_reel/*` не тронуты: заменитель подан через
объявленную точку внедрения `prober=`, а не правкой модуля (Ц2).
