# Железо под форк: что замерено, что выведено, что неизвестно

Этот файл появился как исправление. В плане спринта стояло «рекомендация —
48 ГБ VRAM», и это была не рекомендация, а домысел, выданный за замер: я взял
размер файла весов (17.14 ГБ) и молча предположил, что он целиком лежит в
памяти. Владелец возразил, что у него сервер на 16 ГБ и что требования
завышены. **Возражение верное.** Ниже — то, что можно проверить командой.

**Всё, что ниже, пересчитывается одной командой** — она и есть ответ на
«чем проверить»:

```
python3 docs/measure_hardware.py            # заголовок весов, бюджет, лицензии
python3 docs/measure_hardware.py --offline   # только арифметика, без сети
```

Три состояния помечены прямо: **ЗАМЕРЕНО** — снято командой, команда рядом;
**ВЫВЕДЕНО** — арифметика из замеренных величин, с явными допущениями;
**НЕИЗВЕСТНО** — проверяется только запуском.

## 1. Официального минимума VRAM не существует

**ЗАМЕРЕНО.** Туториал вендора (`workflows/upstream/`, скачан 17 августа) не
называет ни одного числа. Единственное упоминание памяти во всём документе:

> «If you are running this workflow for the first time, please use a small size
> for video generation, in case you don't have enough VRAM»

Ни минимума, ни рекомендации, ни таблицы. Всякое число «нужно N ГБ», названное
без прогона, — чужой домысел или мой. Это стоит помнить, читая форумы.

```
grep -inE 'vram|memory|gb' workflows/upstream/*.md
```

## 2. Устройство модели. Почему размер файла ≠ требуемая память

**ЗАМЕРЕНО** чтением заголовка safetensors range-запросом — без скачивания
17 ГБ. Заголовок весит 195 800 байт:

```
python3 - <<'EOF'
import json, struct, subprocess
U="https://huggingface.co/Kijai/WanVideo_comfy_fp8_scaled/resolve/main/Wan22Animate/Wan2_2-Animate-14B_fp8_e4m3fn_scaled_KJ.safetensors"
r=lambda a,b: subprocess.run(["curl","-sL","-H",f"Range: bytes={a}-{b}",U],capture_output=True).stdout
n=struct.unpack("<Q", r(0,7)[:8])[0]
h=json.loads(r(8,8+n-1)[:n]); h.pop("__metadata__",None)
print(len(h),"тензоров")
EOF
```

Результат:

| величина | значение |
|---|---|
| тензоров | 1922 |
| трансформерных блоков | **40** |
| каждый блок | **0.3762 ГБ**, все сорок ровно одинаковы |
| все блоки вместе | 15.049 ГБ |
| неблочная часть | **2.0885 ГБ**, из них `face_adapter` 1.5628 |
| типы | 15.039 ГБ `F8_E4M3` + 2.099 ГБ `BF16` |
| размерности | `dim` 5120, `ffn` 13824, патч `(1,2,2)` |

Два наблюдения, которые важнее суммы.

**Первое: блоки равны и их сорок.** Это то, что делает поблочную выгрузку
осмысленной: резидентной обязана быть неблочная часть плюс столько блоков,
сколько влезло, а не все сразу.

**Второе:** `face_adapter` на **1.5628 ГБ** — отдельная подсистема под канал
лица, с собственными `linear1_kv [10240,5120]`, `linear1_q`, `linear2` в каждом
fuser-блоке. Плюс `face_encoder`, `motion_encoder` и отдельное
`pose_patch_embedding [5120,16,1,2,2]` рядом с основным
`patch_embedding [5120,36,1,2,2]`. Мимика из драйвинга — не обещание в
маркетинге, а полтора гигабайта параметров и отдельный вход в архитектуре.

## 3. Comfy рассчитан на модели, которые не влезают

**ЗАМЕРЕНО** чтением `comfy/model_management.py` и `comfy/cli_args.py`:

| факт | где |
|---|---|
| `partially_load(device, extra_memory, …)` — частичная загрузка весов штатный путь, а не аварийный | `model_management.py:818` |
| `lowvram_model_memory` считается от **свободной** памяти, а не от размера модели | `:995` |
| `MIN_WEIGHT_MEMORY_RATIO = 0.4` | `:454` |
| `minimum_inference_memory() = 0.8 ГБ + extra_reserved_memory()` | `:860` |
| `extra_reserved_memory()` = **0.40 ГБ** на Linux, 0.60 на Windows | `:847–851` |
| динамический VRAM включён **по умолчанию** — выключается флагом `--disable-dynamic-vram` | `cli_args.py:315` |
| **«By default models will be unloaded to CPU memory after being used»** — это описание флага `--highvram`, то есть выгрузка и есть поведение по умолчанию | `cli_args.py:169` |
| `--lowvram` — «makes the text encoders run on the CPU» | `cli_args.py:170` |
| `--novram` — «when lowvram isn't enough» | `cli_args.py:171` |

Итого на Linux Comfy держит свободными около **1.20 ГБ** и грузит веса ровно
настолько, насколько хватает места. Утверждение «нужно 48 ГБ, потому что файл
17 ГБ» противоречит устройству загрузчика.

## 5. Активации. ВЫВЕДЕНО, с явными допущениями

Токенов на прогон считается из **замеренных** размерностей. Допущения, которые
не из заголовка и потому названы: VAE сжимает 8× по пространству и 4× по
времени; внимание эффективное (SDPA/Sage), то есть O(N) по памяти, а не O(N²).

| размер | кадров | латент | токенов | активации на блок |
|---|---|---|---|---|
| 640×640 | 77 | 20×40×40 | 32 000 | 2.04 ГБ |
| 832×480 | 77 | 20×30×52 | 31 200 | 1.99 ГБ |
| 640×640 | 49 | 13×40×40 | 20 800 | 1.33 ГБ |
| 480×480 | 77 | 20×30×30 | 18 000 | 1.15 ГБ |
| 512×512 | 49 | 13×32×32 | 13 312 | 0.85 ГБ |

Формула: `(4·N·dim + N·ffn) · 2 байта`, где 4 — на q, k, v и выход.

**Латенты сами по себе ничтожны:** 20×80×80×16 в fp16 — это около 4 МБ. Если бы
я посчитал это в первой редакции, вывод про 48 ГБ не появился бы.

Складывая замеренное с выведенным для карты на 16 ГБ:

```
Q5_K_M веса                     12.11 GB
активации при 640x640x77         2.04 GB
резерв Comfy на Linux            1.20 GB
                                --------
                                15.35 GB   впритык, но в габарит
Q4_K_M вместо Q5_K_M            13.95 GB   с запасом
Q5_K_M при 49 кадрах            14.64 GB   с запасом
fp8 целиком + поблочная выгрузка резидентно 2.09 + 0.38 на блок
```

**НЕИЗВЕСТНО и проверяется только запуском:** пик при декоде VAE 77 кадров
(у Comfy есть тайловый декод, но цена не замерена); фактическая фрагментация
памяти; скорость при поблочной выгрузке — она обменивает память на время, и
обмен не измерен.

**Вывод, который я готов защищать:** 16 ГБ — рабочая конфигурация, начинать
надо с Q5_K_M при 640×640 и 49–77 кадрах. Прежняя «рекомендация 48 ГБ» снята
как необоснованная. Локальная 3050 на 8 ГБ остаётся непригодной — но теперь это
следствие 6–8 ГБ квантов против 8 ГБ карты с системой, а не следствие 17 ГБ.

## 6. Лицензии: одна дыра, и она не закрывается заменой

**ЗАМЕРЕНО** по модельному эндпойнту HF для каждого репозитория отдельно.

> Отдельно про метод: сначала я проверял лицензии **поисковым** эндпойнтом
> (`/api/models?search=…`) и получил `license=None` почти у всех, включая
> официальные. Это артефакт: поиск не отдаёт `cardData`. Правильный адрес —
> `/api/models/<owner>/<repo>`. Ложная тревога была моя.

| что | откуда в темплейте | лицензия |
|---|---|---|
| базовая модель | `Wan-AI/Wan2.2-Animate-14B` | **apache-2.0** ✓ |
| fp8-репак | `Kijai/WanVideo_comfy_fp8_scaled` | **apache-2.0** ✓ |
| GGUF-кванты | `QuantStack/Wan2.2-Animate-14B-GGUF` | **apache-2.0** ✓ |
| нода GGUF | `city96/ComfyUI-GGUF` | **Apache-2.0** ✓ |
| VAE, text encoder, clip vision | `Comfy-Org/Wan_*_Repackaged` | **apache-2.0** ✓ |
| темплейт воркфлоу | `Comfy-Org/workflow_templates` | **MIT** ✓ |
| DWPose + YOLOX | уже в репозитории | **apache-2.0** ✓ |
| **step-distill LoRA** | `Kijai/WanVideo_comfy` | **не объявлена** ✗ |
| **relight LoRA** | `Kijai/WanVideo_comfy` | **не объявлена** ✗ |

Оба LoRA из штатного темплейта лежат в репозитории **без объявленной
лицензии**. Замена не нашлась: `lightx2v/Wan2.2-Distill-Loras` действительно
apache-2.0, но содержит только A14B high/low-noise для i2v и t2v — не тот файл,
который стоит в animate-темплейте (`Wan2.1-I2V-14B-480p` rank64). Под relight
апачевого аналога нет вовсе.

**Чем это стоит, если LoRA не брать** — а для коммерческого продукта по
умолчанию не брать:

* **step-distill.** Из темплейта: `steps 6, cfg 1`. Без дистилляции — обычная
  выборка Wan, порядка 20+ шагов при cfg > 1. Это примерно **вчетверо-впятеро
  дороже за клип**. Возможность не теряется, теряется скорость;
* **relight.** Персонаж не досвечивается под сцену. Качество, не возможность.

Решение владельца, не моё: (а) запросить лицензию у автора весов, (б) принять
риск, (в) считать шаги без дистилляции и заложить это в стоимость аренды.
**До решения MVP планируется по варианту (в)** — он единственный, где ничего не
надо ни у кого спрашивать. Официальный `Wan2.2-Animate-2-14B-Distilled` от
самих авторов **apache-2.0**, но это ветка Animate-2, у ноды которой нет ни
`character_mask`, ни `background_video` — то есть не наш путь.

## 7. Диск

**ЗАМЕРЕНО** `curl -sIL` по URL из записки темплейта:

```
animate-14B fp8 (Kijai)      17.14 GB       ИЛИ  Q5_K_M   12.11 GB
umt5-xxl fp8                  6.27 GB
clip_vision_h                 1.18 GB
wan 2.1 vae                   0.24 GB
                             --------            --------
путь fp8, без LoRA           24.83 GB            19.80 GB  путь GGUF
```

Плюс окружение: torch с CUDA, ComfyUI, DWPose. **60 ГБ хватает с запасом**
для пути GGUF без LoRA. Прежнее «≥ 100 ГБ» тоже было завышено.

**Экономия, специфичная для нашего продукта:** промпт один на темплейт, значит
текстовое условие считается **один раз и кладётся в кэш**. Тогда `umt5-xxl` на
6.27 ГБ не нужен ни на диске рабочей машины, ни в памяти во время рендера —
только один раз при заготовке темплейта. Это снимает крупнейшую после самой
UNET позицию.

## 8. Что теперь проверяет предполёт

Не «есть ли 48 ГБ», а измеримое:

1. свободная VRAM в мегабайтах — и подбор кванта под неё по таблице §4;
2. свободный диск против суммы выбранного набора;
3. доступна ли эффективная реализация внимания — от неё зависит §5;
4. наличие каждого файла по хэшу;
5. **лицензионный шлюз: если в дереве нашлись LoRA из `Kijai/WanVideo_comfy` —
   предполёт красный, пока владелец не примет решение из §6.**
