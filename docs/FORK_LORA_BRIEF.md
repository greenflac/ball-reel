## Где работаешь

Репозиторий `greenflac/ball-reel`, ветка `fork/template-mvp`. Прочитать первым
делом `docs/FORK_SPRINT1.md` — там продуктовая задача и логика целиком; §3a — про
эту LoRA. Пул-реквест не открывать. **Существующие файлы не править ни один:**
пайплайн сдан и лежит на внешнем аудите. Всё новое — с приставкой `fork_`.

Сверить состояние прогоном, а не поверить: `python3 -m ball_reel.codeaudit --quick`,
ожидаемые числа в `docs/NUMBERS.md`. Расхождение — находка, важнее плана.

## Продукт в трёх строках

Вход: **одна фотография** клиента и **готовый драйвинг-ролик** со всей
драматургией. Выход: тот же ролик, где персонаж — человек с фотографии.
Механизм: Wan 2.2 Animate в режиме **Mix** — маска очерчивает персонажа, внутри
маски модель перерисовывает его, вне маски кадры драйвинга идут нетронутыми.
Съёмок нет и не будет.

## Твоя задача

**LoRA привязана к темплейту и отвечает за телосложение и домен отрисовки.**

Под каждый темплейт собирается набор с учётом типовой фигуры — «женщина за 40 с
большими бёдрами», «аниме, молодой мужчина» — и LoRA учится один раз, при сборке
темплейта. Каждый клиент, выбравший темплейт, получает её готовой. **Обучения на
клиента нет:** стоимость растёт с каталогом, а не с числом клиентов.

### За что LoRA НЕ отвечает, и почему это важно

| не отвечает | кто отвечает | почему не она |
|---|---|---|
| личность, лицо | референсное изображение | у модели под это выделенный `face_adapter` на 1.5628 ГБ; см. запрет ниже |
| движение | канал позы из DWPose | |
| мимика, губы | отдельный канал лица | |
| окружение, реквизит, другие люди | драйвинг вне маски | она туда физически не достаёт |
| **фактура и размытие** | **ничто. `style.py` удалён из стека** | умеет только смягчать, решение владельца |
| освещение под сцену | `WanAnimate_relight` LoRA вендора | стоит в штатном темплейте, весом 1.0 |

**«Влияет только на персонажа» — верно по устройству, а не по договорённости.**
В режиме Mix вне маски пиксели **вообще не генерируются**, они копируются из
драйвинга. Оговорка честности: `BlockifyMask[32]` грубит маску, поэтому кайма
фона шириной до 32 px попадает в перерисовку. Немного, но не ноль.

## Запрет, который не обсуждается: LoRA личности не учим

Пробовали, замерено. Набор синтезировали из одной фотографии, и он дал **0/21
против сырой фотографии при медиане 0.5067** — по планке проекта это **не тот
человек**. Против медоида самого набора — 19/21 и 0.2579, то есть выглядело
успехом. Отрицательный контроль 0.96–1.05.

Механизм провала: **LoRA даёт согласованность, а не достоверность.** Обученная на
уехавшем наборе, она воспроизводит уехавшего человека устойчиво, и провал
становится труднее заметить.

**Почему твоя задача этим не отравлена.** У категории нет истины, от которой можно
уехать: «женщина за 40 с большими бёдрами» — любой правдоподобный представитель
верен. Механизм того провала здесь структурно отсутствует. Но риск-мутант есть,
см. ниже.

## Что сделать. Всё без GPU

1. **Рецепт набора.** Как собрать набор под тип фигуры так, чтобы **не притащить
   лица**. Направление: кропы тела с исключёнными лицами, низкий ранг ради
   низкочастотной составляющей. Обосновать выбор, а не объявить.
2. **Выбор тренера.** Чем вообще учат LoRA для Wan 2.2 Animate. Выбирать по
   тому, работает ли, а не по лицензии: **на этапе разработки лицензия не
   блокирует** — прогон на своей машине не есть распространение. Что нашлось
   без объявленной лицензии — одной строкой в учёт, к отгрузке, и дальше по делу.
   Если проверяешь, то **модельным** эндпойнтом HF, а не поисковым: поисковый не
   отдаёт `cardData` и врёт `None` даже про официальные репозитории.
3. **Код сборки набора** — новый модуль с приставкой `fork_`, свои тесты.
4. **Приёмка числами** — см. таблицу ниже. Без неё гипотеза неопровержима.
5. **Паспорт темплейта:** какой тип фигуры, какой домен, какой критерий приёмки.

## Опыт, который всё решит: три плеча

Маска и LoRA **не заменяют друг друга**. Маска решает где позволено рисовать,
LoRA — как выглядит тело такого типа. Широкая маска без LoRA: место есть,
заполнить нечем. LoRA без широкой маски: форма известна, обрезается силуэтом.

| плечо | что закрывает исход |
|---|---|
| широкая маска, без LoRA | победило — LoRA не нужна вовсе |
| узкая маска, с LoRA | победило — работа с маской не нужна |
| широкая маска + LoRA | победило — механизм работает целиком |

Три прогона идут **одновременно**, если карт несколько. Один опыт отвечает на три
вопроса, и любой исход что-то закрывает.

## Чем судим

| число | что закрывает |
|---|---|
| `d_raw` до **сырой** фотографии | это тот человек. Якорь только сырое фото, медоид запрещён кодом |
| `d_drv` до лица актёра драйвинга | LoRA не притащила лицо из драйвинга |
| ухудшился ли `d_raw` при включённой LoRA | LoRA не тянет лицо к среднему по категории |
| протечка вне маски против шума сжатия | реквизит и другие люди целы. Ноль недостижим, планку брать из замера шума |
| шовная ось: внутри маски против снаружи, **на одном кадре** | не выглядит вклеенным. На одном кадре — чтобы снять свет, сжатие и момент как объяснения |
| «лицо по кадрам» n/n | личность не уезжает между кадрами |

**Шовную ось писать в форке с нуля.** `style.py` не использовать ни исполнителем,
ни прибором: проверено, что на фактуре он умеет только вычитать — ось `detail`
трогается лишь когда кадр *слишком* детален, ось `noise` измеряется и не
применяется никогда. Своя калибровка: замерить разрыв между облаками на наших
кадрах и поставить порог **внутрь** разрыва. Порог вне разрыва — украшение.

## Аниме ломает метрику. Знать заранее

Домен отрисовки — часть задачи LoRA, и для стилизованного темплейта ArcFace
перестаёт быть верным судьёй: фотографического сходства там не ожидается, а низкое
расстояние до сырого фото означало бы, что **стилизация не сработала**.

Значит критерий приёмки **объявляется у каждого темплейта заранее**, в его
паспорте, а не берётся один на всех. Фотореалистичные — ArcFace против сырого
фото. Стилизованные — иначе либо человеком.

## Предел, который надо знать до сборки набора

Кадрировка во весь рост при высоте 848 даёт лицо **63–80 px** против бара ArcFace
в **100 px** для видео — то есть **«судить нечем»**, а не «плохое сходство».
По пояс даёт 126–159 px. Арифметика и источники — §4a хэндофа.

Практический вывод для тебя: **набор собирается под ту кадрировку, которую
темплейт реально даёт.** Если темплейт по пояс — в наборе тела по пояс, а не в
рост. Иначе LoRA учится на одном масштабе, а применяется на другом.

## Что НЕ делать

* **не выбирать железо и не ставить Comfy** — отдельная сессия;
* **не править существующие файлы** — пайплайн на аудите;
* **не учить LoRA личности** — см. запрет выше;
* **не возвращать `style.py`**;
* **не строить измеритель телосложения с калиброванным порогом.** Нужен
  **маршрутизатор** (§3b хэндофа): три числа из `pose.world_proportions` →
  корзина A / корзина B / **не уверен**. Третий исход обязателен и падает на
  ручной выбор. Порог из когорты для этого не нужен — приёмка есть согласие с
  человеком на горстке примеров;
* **не делать матрицу** «N темплейтов × M фигур». MVP — **один темплейт, две
  фигуры**;
* **не обходить прокси.** Закрыт домен — назвать его и зачем нужен, работать
  дальше без него. Ни зеркал, ни сторонних прокси, ни снятия проверки TLS.

## Правила, которые здесь держатся

* **прежде чем сказать «готово» — прогнать.** Утверждение без прогона не
  принимается;
* **тест, который не умеет краснеть, — украшение.** К каждому порогу проверка,
  что подделанный вход его роняет;
* **число в документе — рядом команда,** которой оно получено;
* **непроверенное помечать НЕПРОВЕРЕНО** и выносить наверх отчёта. На этом проекте
  уже был случай: имя репозитория с весами оказалось выдуманным, и код писался
  против несуществующего API;
* **припоминание — не замер.** Нарушалось дважды за смену: «рекомендация 48 ГБ
  VRAM» и архитектура видеокарты, оба выведены из памяти и поданы как решённые.
  Если источник не команда и не файл — это НЕПРОВЕРЕНО, даже когда звучит
  уверенно;
* **документ, разошедшийся с кодом, — дефект,** а не косметика;
* **закрытые дефекты не стирать, а перечёркивать** с пометкой, чем закрыты.
