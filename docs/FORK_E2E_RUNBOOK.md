# Запуск e2e: от голого VPS до первого ролика

Руководство для того, кто садится за арендованную машину. Каждая команда
здесь либо прогнана в песочнице, либо помечена **НЕПРОВЕРЕНО** — второе
означает, что первый прогон на машине её и проверит.

Три исхода вместо двух действуют и здесь: у всех наших команд код возврата
**0 годно / 1 не годно / 2 не смогли проверить**. Двойка не успех.

---

## 0. Что арендовать

| | значение | откуда |
|---|---|---|
| карта | **одна** A16 (16 ГБ) | демо, батчинга нет |
| ступень весов | **Q4_K_M**, своп 38 блоков | влезает при ОБОИХ допущениях о памяти |
| оперативная память | **от 32 ГБ** | своп переносит на хост 9.5 ГиБ; нехватка даёт не отказ, а замедление в разы |
| диск | **от 60 ГБ** | 18.007 ГиБ весов плюс кадры и выход |
| ОС | Ubuntu 20.04+ / Debian 10+ | требование установщика Claude Code |

**Доступной видеопамяти A16 мы не знаем**: вилка 15.0…15.99 ГиБ, оба конца
выбраны, ни один не наблюдался. Решение Q4_K_M от этого незнания НЕ ЗАВИСИТ —
оно влезает при любом из двух. Первый же `nvidia-smi` на машине закроет вопрос.

## 1. Claude Code на машине

SSH из песочницы разработки невозможен: **порт 22 закрыт** (443 и 80 открыты,
проверено соединением). Поэтому сессия запускается НА САМОЙ машине.

```bash
curl -fsSL https://claude.ai/install.sh | bash
claude --version
```

**Вход без браузера.** На сервере браузера нет, поэтому:

```bash
# на машине С браузером, один раз:
claude setup-token          # выдаёт токен, живёт год, нужна подписка

# на VPS:
export CLAUDE_CODE_OAUTH_TOKEN="<токен>"
```

Либо `export ANTHROPIC_API_KEY="sk-ant-..."` с ключом из консоли.

**Сессия не переживёт обрыв SSH** — она живёт в том же процессе. Обязательно:

```bash
tmux new -s ball    # или screen -S ball
```

**Автономность.** Полный обход разрешений `--dangerously-skip-permissions`
**ОТКАЗЫВАЕТСЯ РАБОТАТЬ ПОД ROOT**. Поэтому: обычный пользователь плюс

```bash
claude --permission-mode dontAsk \
       --allowedTools "Bash(python3 *),Bash(git *),Bash(pip *),Read,Write,Edit"
```

Рут нужен ОДИН РАЗ и руками — на драйвер и системные пакеты.

**НЕПРОВЕРЕНО (Ц4):** у команд есть потолок времени порядка 10 минут.
Загрузка 18 ГиБ и генерация ролика в него не влезут — запускать фоном
(`nohup`, `tmux`, systemd), а сессия следит за логами. Точный потолок и его
переопределение первый прогон уточнит.

## 2. Стек и веса

```bash
git clone <репозиторий> && cd ball-reel && git checkout fork/template-mvp
python3 -m ball_reel.fork_install --comfy /opt/ComfyUI --models /opt/ComfyUI/models --disk /
```

Умолчание — **сухой прогон**: печатает полный план, НИЧЕГО не трогает.
Начать качать 18 ГиБ надо попросить явно (`--install`).

Восемь ступеней от миллисекунд к часам: реестр -> лицензии -> осмотр ->
каталоги -> место -> паки -> зависимости -> веса. Оборваться на последней
из-за отсутствия каталога — это оплаченный час.

Закачка идёт с докачкой прерванного и сверкой **размера И sha256** ПОСЛЕ;
файл кладётся на место только когда сошлось и то, и другое.

**НЕПРОВЕРЕНО:** установщик ни разу не работал по-настоящему — в песочнице
разработки нет сети. Все 96 его тестов идут на подменённом транспорте.

## 3. Приёмка машины — ПЕРВОЙ КОМАНДОЙ

```bash
python3 -m ball_reel.fork_stand --comfy /opt/ComfyUI --models /opt/ComfyUI/models
python3 -m ball_reel.fork_stand --sha    # сверка содержимого, стоит минут
```

**Гонять ДО запуска чего-либо ещё.** Ступень оперативной памяти меряет
ДОСТУПНОЕ СЕЙЧАС; запущенная после ComfyUI, она забракует годную машину — и
будет права по своим меркам.

Семь ступеней: оперативка -> реестр -> размеры -> место -> узлы -> карта ->
sha256. Каждая печатает длительность.

## 4. Материал: от ролика к кадрам драйвинга

```bash
# 1. видео -> кадры
python3 -m ball_reel.fork_video assets/driving_yogaball.mp4 --out work/frames

# 2. кадры -> петли с превью (5 GIF на выбор)
python3 -m ball_reel.fork_looper work/frames --fps 24 --out work/loops

# 3. выбранная петля -> кадры драйвинга нужной длины
python3 -m ball_reel.fork_splice work/frames --loop 114..162 --seconds 6.04 \
        --fps 24 --out work/driving
```

**`--out` не может совпасть с источником.** Склейка стирает кадры в каталоге
назначения ПЕРЕД тем, как прочитать исходные; когда каталог один и тот же,
исходный материал уничтожается. Теперь это ловится до стирания и отвечает
`не годно`, код 1. Проверено: 6 кадров на входе — 6 кадров на месте, читаются.

**`--fps` не перебивает частоту файла.** Если подан видеофайл, частоту снимает
`ffprobe`, и ключ, который с ней не сходится, — отказ с обоими числами, а не
тихий выбор одного. Ключ `--fps 30` на файле 60 к/с раньше выдавал «годно,
5.37 с» там, где реального движения 2.68 с.

**Ролик не бывает короче заказа.** Склейка добирает длину только ВВЕРХ (в
пределах шага обёртки), недостача не допускается ни на кадр: раньше 43%
«годных» планов следующий прибор называл «не хватает».

Числа на боевом материале (ИЗМЕРЕНО в песочнице):

    ролик 720x1278, 24 к/с, 362 кадра, 15.08 с, резов 0, поза на 362 из 362
    лучшая петля 114..162 = 49 кадров = 2.04 с, выигрыш 7.09x
    3 повтора = 145 кадров = 6.04 с; стыковой кадр НЕ дублируется
    склейка кладёт жёсткие ссылки: 0 своих байт вместо 108.7 МиБ копией

**Частота выхода наследуется**: драйвинг 24 к/с — ролик 24 к/с. Выше 30 не
поднимаем никогда.

## 5. Прогон

Карточка (`template.json`) — единственное, что заводит оператор:

```json
{ "schema": "fork-template/1", "name": "первый e2e",
  "driving": "work/driving", "photo": "assets/photoref_profile.jpg",
  "prompt": "...", "negative": "",
  "fps": 24, "width": 480, "height": 832, "seconds": 6.04,
  "step": "Q4_K_M", "arm": "auto", "face_refine": false }
```

```bash
python3 -m ball_reel.fork_template work/template.json          # только проверка
python3 -m ball_reel.fork_run work/template.json --out work/out \
        --backend 127.0.0.1:8188 --production
```

Одиннадцать шагов, у каждого свой исход и своя длительность. Без `--backend`
шаг рендера честно отвечает «не смогли»: сервера нет.

**Ступени печатаются по ходу, на stderr.** Это важно именно на арендованной
карте: сквозной прогон на боевом материале идёт десятки минут, и пока он
молчал, «работает» и «повисло» были неразличимы — один такой прогон уже упёрся
в потолок времени и унёс с собой всё измеренное. Отчёт по-прежнему уходит на
stdout целиком, поэтому `--json` разбирается машиной как раньше:

```bash
python3 -m ball_reel.fork_run work/template.json --out work/out --json \
        2> work/progress.log > work/report.json
```

## 7. Что нельзя обещать клиенту

Липсинк (прибора нет, вопрос не ставился), звук (модель его не порождает,
решения нет), реализм кожи (ось снята решением), татуировки (канала текстуры
у модели нет), сходство лица на общем плане (выходит 66-68 px при планке
измеримости 100).

Обещать можно формат — вертикаль 480x832, частота как у драйвинга, 5-10 с — и
что фон, свет и движение наследуются из драйвинга.

## 8. Куда смотреть, когда что-то не так

| симптом | первый подозреваемый |
|---|---|
| «долго считает», карта не загружена | не хватило ОЗУ, ушли в своп на диск |
| приёмка бракует годную машину | запущена ПОСЛЕ ComfyUI, память уже занята |
| ролик короче заказанного | частота драйвинга не 30; смотреть шаг «длина» |
| рывок при повторе | петля выбрана без учёта головы; см. слепые зоны |
| «граф не годен» на новой ноде | реестр имён виджетов её не знает; это «не смогли», а не брак графа |
| личность не измеряется | лицо мельче 100 px; нужен кроп-прогон |

## 9. Перфект луп: как он устроен у нас

Идеальной петли в снятом материале не бывает — **подгонка нужна всегда**, и
это решение владельца, а не обходной путь. Отсюда вся раскладка:

```
рендерится ОДИН непрерывный отрезок драйвинга:

   кадры 65..113          кадры 114..161         мост
   └─ подводка 49 ────┘   └─ тело круга 48 ──┘   └─ 4 ─┘
          ▲                        ▲
    стык лечить не надо      единственный мост
   (кадры идут подряд)        во всём ролике

выдача: подводка играется ОДИН раз, дальше круг крутится плеером бесконечно
```

**Мост** — это промежуточные кадры позы между концом круга и его началом.
Длина моста не выдумана: наша мера стыка уже считается **в типичных
межкадровых шагах клипа**, поэтому «стык 3.9» буквально значит «не хватает
примерно четырёх кадров обычного движения», и мост в 4 кадра проводит переход
с нормальной скоростью. Синтетических кадров получается 4 из 101.

**Что это даёт по деньгам.** Прогон 101 кадр — 2 окна, ~90 с счёта по нашей
оценке: **та же цена карты, что за шестисекундный ролик сегодня**, но на
выходе видео любой длины, вплоть до бесконечной. Повтор перестаёт быть
работой модели и становится работой плеера.

**Что проверять на каждой карточке:**

| проверка | почему | исход, если не так |
|---|---|---|
| подводка существует | нужно L кадров перед петлёй | не смогли — круг без подводки годен |
| в подводке нет монтажного реза | смена плана до начала круга | не годно |
| длина ложится на шаг 4k+1 | обёртка прижмёт вниз МОЛЧА и оборвёт круг | подгоняется подводка |
| ни одна ось стыка не «не смогли» | неизмеренная ось ведёт себя как ноль и **поднимает** петлю в рейтинге | см. ниже |

Последняя строка — не теория. ИЗМЕРЕНО 20.08 на боевом ролике: петля 309..357
обошла петлю 114..162 (выигрыш 4.79× против 2.95×) только потому, что на её
первом кадре не видно лица и ось головы не отработала. Настоящий стык головы у
неё **12.49** типичных шага против 3.48 у соперницы. Владелец увидел это
глазами на гифке раньше, чем приёмка.
