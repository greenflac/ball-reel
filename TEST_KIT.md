# Тест-кит: что распаковать и в каком порядке запускать

Всё, что нельзя посчитать на твоём ноуте быстро, посчитано заранее. В ките
лежат уже отрендеренные условия ControlNet, driving-кадры, к которым они
привязаны, и фото лица. Твоей карте остаётся только рисовать.

```
kit/
  conditions/      71 png 512x768 + manifest.json  — то, чем ControlNet держит позу
  driving/         71 jpg                          — исходные кадры, ими проверяется поза
  face.jpg         фото лица                       — им проверяется личность
```

**Что уже измерено на этих входах** (ничего из этого повторять не надо):

| что | значение |
|---|---|
| источник условий | DWPose (не MediaPipe — он остаётся судьёй) |
| ретаргет под телосложение с фото | да |
| покрытие кадров | 1.00 |
| покрытие суставов | 0.97 |
| кадров с потерянной конечностью | 5 из 71 |
| лицо на `face.jpg` | 148 px, детектор 0.819 |
| длина отрезка | 71 кадр = 5.9 c при 12 fps |

Детектор здесь был записан как 0.87 — перепроверено `intake.inspect` и
`identity_arcface.face_detail` на самом файле: 0.819. Порог `MIN_DETECTOR_SCORE`
равен 0.6, так что вывод «фото годится» не меняется, но число было не то.

**Манифест этого кита отрендерен ДО того, как в `skeleton.render_sequence`
появилась кадрировка.** В `kit/conditions/manifest.json` нет ключей `framing`,
`face_share`, `face_px`, `identity_judgeable` — они появились позже. Практическое
следствие: `run_local` напечатает «манифест не называет кадрировку (условия
отрендерены старым skeleton)» и возьмёт НАМЕРЕНИЕ флага, а не свидетельство
условий, — то есть прогноз «увидит ли гейт лицо» на этом ките будет
недостоверен. Перерендерить условия текущим кодом или читать прогноз как
догадку.

Отрезок именно 71 кадр, а не все 96: в кадрах 71 и 75 скелет не нашёлся, а
дырка посреди последовательности — это не «кадра нет», а «шаг по времени в этом
месте другой». Взят самый длинный непрерывный кусок. Заодно он оказался чище
целого: частичных кадров 5 против 19.

## 0. Развернуть

Кит приходит отдельным файлом `ball_reel_kit.tar.gz` (7 МБ) — в git он не
лежит намеренно, это бинарь.

```bash
git clone -b claude/ball-reel-mvp-pollinations-ruasf1 <repo> && cd llm_radar/ball_reel
tar xzf ~/Downloads/ball_reel_kit.tar.gz     # появится kit/
export POLLINATIONS_API_KEY=sk_...           # нужен только на шаге 4
```

Зависимости под карту:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu126
pip install "diffusers>=0.27" transformers accelerate safetensors peft
pip install insightface onnxruntime mediapipe pillow numpy requests huggingface_hub
```

Версию CUDA в индексе подбирать под свой Python: индексы pytorch.org собраны
под конкретные интерпретаторы, и `cu121` на Python 3.13+ отдаёт «No matching
distribution» — сообщение, по которому не догадаться, что дело в версии
интерпретатора, а не в CUDA. Актуальный индекс — на
https://pytorch.org/get-started/locally/

`onnxruntime`, а не `onnxruntime-gpu`: он нужен только для распознавания лица
на десятке картинок, и gpu-версия под Windows тянет за собой возню с cuDNN.

**В PowerShell** кавычки вокруг `"diffusers>=0.27"` обязательны: `>` там —
оператор перенаправления, и без кавычек pip создаст файл вместо установки.
Там же `%USERPROFILE%` не раскрывается (нужно `$env:USERPROFILE`), а `curl` —
псевдоним `Invoke-WebRequest` и флагов настоящего curl не понимает.

`insightface` тут не опционален: FaceID обусловливается вектором ArcFace, и
берётся он у того же анализатора, которым лицо потом проверяется.

## 1. Убедиться, что офлайн-часть цела (бесплатно, ~1.5 мин)

```bash
python3 -m ball_reel.codeaudit --quick
```

Ожидается зелёная строка вида `PASS  тесты  Ran 631 tests in 63.9s` (реальный
вывод на 2026-08-14; `--quick` считает ещё и покрытие, отсюда полторы минуты, а
не секунда). **Сверять слово `PASS`, а не число тестов**: набор растёт каждую
сессию, и записанное здесь число устареет раньше, чем ты его прочитаешь. Здесь
уже стояло «Ran 249 tests» — на момент правки их было 631.

Если красное — дальше не идти, дело не в карте.

## 2. Предполёт (бесплатно, ~10 с)

```bash
python3 -m ball_reel.preflight_gpu --conditions kit/conditions --face kit/face.jpg
```

**Из корня репозитория, а не из `kit/`.** Здесь стояло `cd kit` — и вся команда
падала `ModuleNotFoundError: No module named 'ball_reel'`: пакет лежит в корне,
а `python3 -m` ищет его от текущего каталога. Проверено запуском.

Девять проверок по порядку удорожания (диск, torch, onnxruntime, vram, веса,
модель позы, условия, лицо, шлюз), первая же неудача останавливает всё. С
`--skip-gateway` их восемь — последняя, единственная сетевая, отпадает.
Здесь и выяснится реальный объём карты — строка `vram`. Пришли её мне: под
3050 план может уйти на 448x640, и лучше это решить до генерации.

Первый запуск качает ~7 ГБ весов (SD1.5 + ControlNet + FaceID). Проверка
`веса` для того и стоит перед всем остальным.

## 3. Дым: ОДИН кейфрейм (бесплатно, секунды)

```bash
python3 -m ball_reel.run_local --engine chain \
  --face kit/face.jpg --conditions kit/conditions \
  --prompt "a woman exercising on a fitness ball in a bright studio, black sports top and grey leggings, natural light, photographic" \
  --smoke
```

**`--engine chain` обязателен, и это изменилось.** Умолчание `run_local` теперь
`animatediff` — локальный путь без единого сетевого вызова в генерации. У него
`--smoke` делает другое: останавливается после сборки весов и печати
прицепленных LoRA, отдельного дешёвого кадра там нет, потому что кадры
считаются совместно. Шаги 3–4 этого документа описывают именно `chain`.

Печатает два числа и останавливается:

| метрика | бар | если хуже |
|---|---|---|
| дрифт лица | ≤ 0.35 (`identity_arcface.SAME_PERSON_MAX`) | поднять `ip_adapter_scale` до 0.85 |
| поза, среднее | ≤ 0.15 (`pose.SAME_POSE_MAX`) | поднять `controlnet_scale` до 1.2 |
| поза, худший сустав | ≤ 0.40 (`pose.WORST_JOINT_MAX`) | то же |

Здесь было записано «поза, среднее ≤ 0.25». Это был бар шлюзового кейфрейма
(`chain.KEYFRAME_POSE_MAX`), а не старт-кадра, и он на две трети мягче того,
что реально проверяет `run_local.smoke_verdict`. Худший сустав печатался, но в
вердикт не входил, — теперь входит: среднее размывает уехавшую руку (замер в
коде: согнутая рука даёт среднее 0.11 при запястье 0.97).

Один кадр стоит секунды, полный прогон — минуты. Крутить параметры надо
здесь, а не после.

**Если поза печатается как «НЕ ИЗМЕРЕНА» — это провал, а не пропуск.** Раньше
эта проверка молча считалась пройденной; теперь нет.

## 4. Полный прогон (единственный платный шаг)

```bash
python3 -m ball_reel.run_local --engine chain \
  --face kit/face.jpg --conditions kit/conditions \
  --prompt "..." --video-model wan-fast --seconds 2 --every 12
```

`--every 12` на 71 условии даёт 6 узлов и клип ~12 c: 6 сегментов × 2 c × 0.01 =
**0.12 pollen**. `--every 6` даёт 12 узлов и 24 c — плотнее держит траекторию,
вдвое дороже. Стоимость печатается ДО вызова.

`--every`, `--seconds`, `--video-model` относятся ТОЛЬКО к `--engine chain`; на
`animatediff` они игнорируются, потому что там кадры не узлы, а окно.

`wan-fast` дешевле `seedance-2.0` в 18 раз (0.01 против 0.18 pollen за секунду
видео). Переключаться на дорогую модель имеет смысл только когда связка уже
сошлась. Осторожно: `seedance-2.0` принимает от 4 c, `veo` — ровно 4/6/8; прогон
это проверит до генерации (`chain.segment_seconds_ok`).

## 5. Что смотреть в результате

`run_out/report.json`. Строк гейта больше пяти: сначала блок одежды и мимики
(`одежда`, `прилегание`, `мимика` — `run_local.wardrobe_rows`), затем клиповые
(`идентичность`, `луп`, `движение`, `анатомия`, и `одежда` ещё раз, если кадры
клипа — другой набор, чем узлы). Клип на пути `chain` — `run_out/chain/chain.mp4`,
на пути `animatediff` — `run_out/clip.mp4`.

`прилегание` и `мимика` намеренно **не останавливают прогон**: ни один из этих
двух измерителей ни разу не работал на сгенерированном клипе, только на живой
съёмке, и ставить бар на непроверенном приборе — это ровно то самое «выдать
выбранное за измеренное».

Гейт может честно сказать «NOT VERIFIABLE» по лицу — это не «другой человек», а
«лицо в кадре мельче 100 px, судить не по чему». Лечится кадрированием, а не
параметрами.

## Чего этот кит НЕ проверяет

- **Одежду референсом.** `--garment-ref` откажет: единственный адаптер занят
  лицом, второй референс требует второго IP-Adapter'а и на железе не проверялся.
  Одежду задаёт текст промта — держи формулировку побуквенно одинаковой.
- **Мяч.** Совпадение объекта не меряется ни одной метрикой. Смотреть глазами.
- **Камеру.** Движение камеры не отделено от движения субъекта.
